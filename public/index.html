From paper to proof in four steps

Each credential follows the same path, and each step can be checked independently.

1

Fingerprint

The registrar drops the diploma. Its SHA-256 digest is computed and the file itself stays private.

2

Anchor

The digest, issuer and timestamp are written to the ledger. It cannot be edited afterwards.

3

Share

A QR code is generated and printed on the credential or sent with the PDF.

4

Verify

An employer scans the QR or drops the file. A match means authentic; any edit means tampered.

Questions evaluators ask

Is my document uploaded anywhere?

Only the fingerprint matters to the ledger. In the live app, hashing happens in the browser, and the file is never stored by the verifier.

What if someone changes a single letter?

The SHA-256 changes completely. Try it in the Tamper Lab and see how many of the 64 characters flip.

Can a credential be cancelled?

Yes. The issuer can revoke it from the Issuer Portal. The original record stays on the ledger, but verification then reports REVOKED.

Does verifying cost anything?

No. Verification is a read-only lookup, so it needs no wallet, tokens or network fees.

Is this connected to a real blockchain?

This demo uses a simulated ledger for speed. The contract design supports Polygon or Ethereum testnets, and only the anchoring function changes.
